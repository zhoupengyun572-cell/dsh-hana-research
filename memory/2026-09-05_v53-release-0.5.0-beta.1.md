### 安装冒烟（干净环境，记录实际边界）

- `npm pack` 真实 tgz → 全新 `DSH_HOME`（临时目录）→ `dsh plugin --profile smoke05 add <tgz>`：**安装成功**（pnpm 118 包、package.json 声明 file:tgz、包内 cordis.patch.yml 与 dsh.bundle 字段完整落位）。
- **bundle 自动挂载确认生效**：boot 时 dsh.bundle 被自动扫描（手写 insert 条目反而触发 duplicate loader entry 冲突，移除后正常）。
- ⚠️ **干净 profile 的 web UI 启动未走通（环境准备问题，非插件缺陷）**：`dsh plugin add` 只装插件包，smoke profile 缺 web 运行时（@deepseek-ai/dsh-web-app 等不在依赖树），根命令 boot 报「hana-research: pending (waiting for service: webServer)」；`dsh web` 子命令固定 boot `web` profile（help 明示 alias of --profile web），不接受 --profile。结论：干净环境一键安装的完整形态需要 web profile 基座（R1 验收时的形态）；把「冒烟 profile 如何获得 web 运行时」记为待确认项。
- **真实环境版本验证 ✅**：`~/.dsh` web profile 启动后 health = `{"ok":true,"schemaVersion":22,"releaseVersion":"0.5.0-beta.1"}`，前端页 HTTP 200。
- 环境坑备案：dsh 子进程需要 pnpm 在 PATH（本机 pnpm 经 corepack 提供，`corepack enable --install-directory <dir>` 造 shim 后放入 PATH）；**带空格的 Windows 路径会让 pnpm add 截断失败**（`deep seek` 目录 → tgz 需拷到无空格路径再装）；后台实例残留端口会导致 EADDRINUSE 干扰判断。
